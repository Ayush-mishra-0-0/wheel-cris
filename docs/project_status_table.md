# Project Status Table

**Problem Statement:** Build a wheel-health intelligence platform for the railway fleet that fuses wheel measurement, maintenance, and operational data to detect abnormal wear, estimate remaining life (RUL), and recommend where maintenance engineers should inspect next — with explainable "likely contributing factors" rather than a black-box model.

| Problem Statement | IP Variables | Remarks |
|---|---|---|
| Track each wheel/wheelset and know which locomotive it was fitted on at every point in time. | Wheel measurements, equipment register, locomotive assignment history | **Done:** Wheel-to-locomotive mapping built for the WAP7 fleet; 85% of history confidently mapped, rest quarantined for audit. **PDC:** Confirm wheel identity semantics with domain owner and close coverage gaps. |
| Define clean, valid time intervals between consecutive wheel inspections so progress can be measured consistently. | Gold-B wheel timeline | **Done:** 225k valid inspection intervals released and quality-validated. **PDC:** Use as the fixed foundation for all downstream features. |
| Know how far a locomotive actually travelled between inspections (km) — the main missing enabler for wear-per-km. | RTIS mileage source, FOIS movement/track data | **Done:** Mileage source identified and loaded; raw aggregation still under source-owner review. **PDC:** Get approval on distance calculation from source owner or acquire track-network data. |
| Convert raw wheel geometry changes into a defensible "wear" measure. | Wheel geometry fields (diameter, flange, tread), turning/reprofiling flags | **Done:** Measurement semantics documented field-by-field over ~1M intervals. **PDC:** Engineering sign-off on units and turning/reset rules, then release wear rate. |
| One governed, validated feature layer feeding all analytics and models. | Feature specification (14 features) + feature-store builder | **Done:** Feature store v1.0 released; 7 features usable now, distance and wear-rate correctly locked out. **PDC:** Materialise remaining ready features as gates clear. |
| Reconstruct WAP7 routes/locations and add curve/gradient severity as a wear factor. | FOIS route-history feed, official track-geometry (IR Geoportal) | **Done:** Route-history feed for WAP7 identified; ordered station sequence usable. **PDC:** Acquire official track/chainage network — the single biggest external-data gap. |
| Produce an explainable wheel health/risk score. | Validated geometry + degradation features, approved limits | **Done:** Design blocked until wear rules are approved (by design). **PDC:** Build health rule and release health snapshot once gates clear. |
| Predict abnormal wear, remaining life (RUL), and maintenance priority. | Feature-store outputs; wear-threshold labels | **Done:** No models yet — deliberately gated. First target agreed: flag wheels wearing abnormally fast. **PDC:** Define target, build simple baselines, then a transparent model. |
| Measure whether maintenance (turning/job-cards) actually helps. | Job cards, turning indicators, defect history | **Done:** Maintenance events linked to intervals (creation-time caveat). **PDC:** Confirm event semantics with domain owner; build effectiveness metric and use it to improve the model. |
| Add supporting context (weather, load, emergency events) to explain wear. | Weather archive, axle-load config, emergency-event feed | **Done:** Static axle load ready; emergency events linked. Weather not yet sourced. **PDC:** Validate load, source and cache weather, confirm event meanings. |
