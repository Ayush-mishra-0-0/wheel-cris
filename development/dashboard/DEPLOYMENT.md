# Wheel Lifecycle Dashboard — Deployment Guide

The dashboard is the Layer-5 application in this repo: a FastAPI backend that
serves wheel-profile state, degradation forecasts and turning probability, plus
a React/Vite frontend that consumes it.

- **Backend**: FastAPI + uvicorn, wired to `/api/v1/...` (the contract of record),
  with unversioned aliases for backward compatibility.
- **Frontend**: React + Vite SPA; dev server proxies `/api` -> backend.

## Prerequisites

- **Python >= 3.12** (dependencies pin numpy 2.5, pandas 3.0)
- **Node.js** (Vite 5), **npm** (for the frontend)
- A checkout of this repo with the `ml/` serving artifacts present
  (`ml/model_datasets/v5/fleet_snapshot.parquet` by default)

## Backend Setup

Install the package in editable mode into a dedicated virtualenv (the ML code
and datasets are versioned data under `ml/` and are read from disk; no ML wheel
is built). From the **repo root**:

```powershell
python -m venv ayush
ayush\Scripts\pip install -e .
```

The install exposes two console scripts: `wheel-dashboard` (the API server) and
`wheel-snapshot` (rebuilds the fleet snapshot from the source WES frame).

Verify the backend imports and serving artifacts validate:

```powershell
ayush\Scripts\python -c "from dashboard.backend import api_v1; print('OK')"
```

## Backend Run

Use the console launcher (no PYTHONPATH fiddling; the app injects the `ml` root
itself). Defaults: `http://127.0.0.1:8033`.

```powershell
# Default: http://127.0.0.1:8033
ayush\Scripts\wheel-dashboard

# Custom host/port (0.0.0.0 exposes to the network)
$env:WHEEL_HOST="0.0.0.0"; $env:WHEEL_PORT="8080"
ayush\Scripts\wheel-dashboard

# Custom CORS origins (comma-separated; required when a SLAM host calls the API)
$env:WHEEL_CORS_ORIGINS="https://slam.example.com,http://127.0.0.1:5173"
ayush\Scripts\wheel-dashboard

# Auto-reload during development
$env:WHEEL_RELOAD="1"
ayush\Scripts\wheel-dashboard
```

### Environment overrides (`WHEEL_*`)

| Variable | Default | Description |
| --- | --- | --- |
| `WHEEL_HOST` | `127.0.0.1` | uvicorn bind host |
| `WHEEL_PORT` | `8033` | uvicorn bind port |
| `WHEEL_CORS_ORIGINS` | `http://127.0.0.1:5173,http://localhost:5173` | comma-separated allow-list; never `*` by default |
| `WHEEL_SNAPSHOT_PARQUET` | `ml/model_datasets/v5/fleet_snapshot.parquet` | fleet snapshot for overview/risk endpoints |
| `WHEEL_ENABLE_LEGACY_PLOTS` | `0` | re-enable legacy bulk `/loco/{n}/plots` (loads full WES frame per request) |
| `WHEEL_RELOAD` | `0` | uvicorn auto-reload |
| `WHEEL_DASHBOARD_CONFIG` | `development` | config profile label |

Sane local defaults shipping out of the box; a production deployment must
opt in explicitly to any non-default value (e.g. real CORS origins).

## Frontend Setup

```powershell
cd development\dashboard\frontend
npm install
```

## Frontend Run

```powershell
# Dev server with HMR on http://127.0.0.1:5173 (proxies /api -> backend)
npm run dev

# Production preview: build, then serve the static bundle
npm run build
npm run preview
```

## Health Check

Liveness/readiness returns `{"status": "ok", "t": <epoch>, "validation": ...}`:

```powershell
Invoke-RestMethod http://127.0.0.1:8033/health
```

`validation.warnings` lists any start-up serving-artifact warnings (the service
validates artifacts at startup and fails fast on a broken artifact set).

## API Documentation (OpenAPI)

OpenAPI is auto-generated by FastAPI; all schemas and endpoints are documented.

- **Swagger UI**: http://127.0.0.1:8033/docs
- **ReDoc**: http://127.0.0.1:8033/redoc
- **OpenAPI JSON**: http://127.0.0.1:8033/openapi.json

All data endpoints are prefixed `/api/v1/` (contract of record); unversioned
aliases exist for migration only and are deprecated.

## Known Limitations

- **No authentication** — the service implements zero auth (no user store,
  sessions, tokens, SSO or RBAC). All endpoints are unauthenticated at the
  module boundary. Authentication must be applied by the SLAM host/proxy.
- **Module boundary only** — this dashboard is intended to be consumed as a
  module inside the SLAM application; it is not a hardened standalone service.
- **CORS defaults to local dev** — production hosts must set
  `WHEEL_CORS_ORIGINS` to the calling application's origins.
- **Legacy bulk loco plots disabled** — use the wheelset trajectory contract
  (`/wheelset/{id}/lifecycle/export`) instead; re-enable via
  `WHEEL_ENABLE_LEGACY_PLOTS=1` if required.
